# 01 项目定位与核心链路

## 1. 系统身份

`HCQ-Agent Core`：运行于 WSL（Ubuntu）的 Python 常驻后端，技术栈为 NoneBot 2 + Python 虚拟环境 + 自研 AUP 工具协议 + 动态插件架构。仓库根目录即运行根目录，运行所用解释器为项目内虚拟环境。

本仓库只包含后端本体；HCQ-Core Desktop、HCQ-Core Mobile、HCQ-Chat Mobile 与两层网关属于独立工程，不在本仓库内，边界见第 4 节。

## 2. 启动入口

唯一启动入口为后端主脚本，以项目虚拟环境解释器运行。启动顺序：先引导导入中心，再动态加载全部插件，最后启动 NoneBot 运行时。

- 适配器按环境变量条件注册，见 [09_配置与模型策略.md]。
- 启动钩子包含后台防御巡检与过期情节记忆清理，见 [10_生产坐标红线与运维规程.md]。

## 3. 通道现状

| 端口 | 现状 | 说明 |
|---|---|---|
| 8082 本地 HTTP 服务 | 常驻 | HCQ-Agent Core 绑定本机回环，承载测试沙盒与模型直达两个路由，只接收网关回环请求 |
| 8083 业务网关 | 常驻回环 | 独立工程，完成身份识别、member 轨迹脱敏、管理端点闸门后转发到 8082 |
| 8084 鉴权网关 | 公网唯一入口 | 独立工程，完成密钥/JWT 校验与身份头注入后反向代理到 8083；对外托管管理面板页 `/panel` 与监控路由 `/api/health`、`/api/kula/*`；外部客户端不直连 8083、8082 |
| 8085 监控面板 | 常驻回环 | KULA 指标采集与 Web UI，只绑定 `127.0.0.1:8085`，不对外 |
| 8086 健康聚合 | 常驻回环 | 多服务健康与指标汇总，只绑定 `127.0.0.1:8086`，由 8083 的 `/api/health` 反向代理读取 |

8082 本地 HTTP 路由：

- 测试沙盒路由：只返回清洗后的回复，不执行对外发送；会话使用专属前缀与真实上下文隔离。
- 模型直达路由：模型身份由入参原样带入，不做策略映射、不静默换模型；`/api/model_chat` 与别名 `/api/strategy_chat` 指向同一处理器。

五端口职责与多端拓扑详见 [13_运行拓扑与多端架构.md]；8082/8085/8086 只绑定回环，8083 由 8084 回环转发，仅 8084 对外。

## 4. 外部边界

- 两层网关与三个客户端壳位于独立工程：8084 鉴权网关监听 `0.0.0.0:8084`，鉴权后转发到回环内的 8083 业务网关；8083 再转发到 8082 模型直达路由。本仓库不维护前端页面、网关转发逻辑与前端会话状态。
- HCQ-Core Desktop、HCQ-Core Mobile、HCQ-Chat Mobile 的壳坐标与连接契约见 [11_多端生态与原生壳.md]；DSH 宿主/前端插件轨道与信任边界见 [12_插件生态与信任边界.md]；完整拓扑见 [13_运行拓扑与多端架构.md]。

## 5. 核心请求链路

```
消息或本地 HTTP 请求
  → 入口层：别名物理前置解析（进模型前完成，不交模型判断）
  → 对话编排：上下文装载、模型选定、意图判定、工具循环
  → 工具汇聚点：注册中心可见性过滤 → 权限检查 → 审计 → 执行
  → 输出清洗：泄漏与违规标记剥离、裸链接与裸 JSON 处理
  → 回复返回（HTTP 响应或 SSE 流，经网关回到客户端）
```

链路各段归属：

- 入口适配与别名解析：详见 [02_主引擎职责.md]
- 意图、模型分支、工具循环与清洗：详见 [03_意图与对话编排.md]
- 工具协议与注册：详见 [05_AUP协议与工具注册.md]
- 权限与审计：详见 [06_权限与审计.md]

## 6. 粗粒度依赖方向

```
入口脚本 → 对话编排 / 工具汇聚点 / 记忆层 / 模型策略 / 插件加载器
对话编排 → 记忆中心 / 模型策略 / 外部通道封装；延迟调用工具汇聚点
工具汇聚点 → AUP 协议层 / 注册中心 / 安全与审计模块
插件层 → 经动态加载器导入；插件之间不被主引擎硬编码引用
```

关键约束：

- 主引擎对插件零硬编码导入，只经动态加载器，见 [07_插件层与扩展契约.md]。
- 所有工具调用必须经过唯一汇聚点，绕过即红线，见 [10_生产坐标红线与运维规程.md]。
- AI 可见工具由注册中心可见性硬控，不由提示词控制，见 [05_AUP协议与工具注册.md]。
