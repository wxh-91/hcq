# 05 AUP 协议与工具注册

> 本文件定义工具可信度的契约层：返回结构、注册门禁、可见性与执行口径。插件如何接入见 [07_插件层与扩展契约.md]；执行时的身份放行见 [06_权限与审计.md]。

## 1. 统一返回结构

所有经协议注册的工具返回同一结构：状态、错误码、数据、降级链。非该结构视为协议违规。

- 业务错误通过约定错误码标识，编排层据此直判结果，不把状态字段交给模型自由总结。
- 工具结果经汇聚点渲染后再进入回复链路；内部参数与结构不直接透传到聊天通道，见 [03_意图与对话编排.md]。

## 2. 协议装饰器门禁

工具必须携带协议装饰器才能注册与调用。装饰器职责：

- 入参校验与类型归一；
- 出参包装为统一返回结构；
- 采集元数据（工具名、描述、参数 schema、分类、危险标记、可见性、版本等）。

未过门门禁的函数不进入注册中心，编排层无法通过工具名调用。

## 3. 注册中心与可见性

- 注册中心持有全部已注册工具的元数据与可调用引用；AI 可见工具由中心按可见性标记过滤，不由提示词描述控制。
- 下线/隐藏工具保持隐藏：启动只导入模块，不重新激活被隐藏的工具。
- 工具元数据缺失可调用引用时，按记录的模块路径与名称动态加载兜底；加载不到则返回未知或不可用。
- 工具描述、参数 schema、可见性变更后，需显式触发一次注册同步，否则注册中心与源码口径不一致。

## 4. 唯一执行入口

所有工具调用经过同一汇聚点执行，顺序为：参数归一化 → 只读配置守卫 → 注册中心查询与可见性拦截 → 权限检查 → 审计 → 执行 → 结果渲染。

- 绕过该汇聚点直接调用工具函数属于红线，见 [10_生产坐标红线与运维规程.md]。
- 汇聚点同时承担心跳等待与异常结果包装，避免长工具阻塞无反馈。

## 5. 口径分离

工具数量必须按边界分开表述，禁止混用：

- **注册总数**：注册中心内记录的全部工具。
- **AI 可见数**：可见性开启、可装配进模型 schema 的工具。
- **隐藏数**：可见性关闭或下线的工具。

查询工具清单时先确认使用的是哪一口径。

## 6. 工具 schema 装配

- 支持工具的模型按注册中心可见工具生成 schema；不支持工具的模型不装配。
- schema 字段由装饰器元数据与参数描述构建；描述用于模型选择工具，不承担权限控制。
- 工具分类用于分组与过滤，不改变执行门禁。

## 7. 何时查本文档

- 工具在模型列表中不可见，或隐藏工具被重新调用。
- 工具返回结构不一致、错误码未被识别。
- 改了工具描述或参数后，模型看到的仍是旧口径。
- 工具调用绕过汇聚点、权限或审计未生效。
- 统计工具数量时口径对不上。
