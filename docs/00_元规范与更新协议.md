# 00 元规范与更新协议

> 本文件约束“文档怎么写、怎么准入、怎么更新”，不描述项目业务。项目结构变化时，本文件原则上不变；变的是各模块文档的现状投影。

## 1. 文档定位

- 本套文档是“可被重复执行的写作规范 + 当前架构投影”，不是某一时刻的目录快照。
- 阅读顺序：先读本文件，再按问题定位到对应模块文档；改某模块时只看该模块及其交叉引用，不通读全套。
- 正文只承载决策相关信息：是否改变下一步行动、在哪定位、缺失或过期的代价、能否运行时重建。

## 2. 信息准入四问

每条拟写入正文的信息，逐条回答：

1. **决策相关性**：是否会改变下一步行动选择？
2. **坐标性**：是定位坐标（叫什么、在哪、何时查），还是内容展开（内部结构、字段细节、实现步骤）？
3. **失效成本**：缺失或过期时，是否会导致错误行动？
4. **可重建性**：能否通过一次检索、一次目录遍历或一次命令在运行时低成本重建？

按四问结果归入四象限：

| 决策相关 | 可重建 | 处置 |
|---|---|---|
| 高 | 不能 | 必留，可展开到契约与边界 |
| 高 | 能 | 只留坐标（名称、用途、何时查），不展开内容 |
| 低 | 不能 | 降级为一句说明 |
| 低 | 能 | 剔除 |

判据必须可复用、可自评、允许标注例外；不得用“因为它属于某目录所以剔除”这类以路径为条件的规则。

## 3. 抽象层级

文档分三层，同一段内不得跨层混写：

- **L-架构**：系统由哪些层组成、层间靠什么契约通信；只写契约名与方向。
- **L-模块**：每个模块的职责边界与触发场景；一句话职责 + 何时查。
- **L-坐标**：运行时产物的名称、位置、查询入口；名称 + 用途 + 何时查，不贴样例内容。

## 4. 信息密度

- 一个条目只承载一个决策点；“是什么”和“内部怎么实现”分开，后者按准入判据降级或剔除。
- 禁止同义复述：目录已写职责，正文不再抄一遍，只补“何时查、失效后果”。
- 同一指标全文只保留一个统计边界；多口径必须显式命名（如注册总数、AI 可见数、隐藏数）。

## 5. 质量分级

- **Q0 阻断级**：无法确定唯一启动入口，或无法区分红线与建议，不可用。
- **Q1 运行级**：能定位入口与主链路，异常场景需回读源码决策。
- **Q2 交接级**：异常场景能按文档定位到文件、日志或状态载体；改动前能判断影响面；红线可执行。
- **Q3 自维护级**：含更新协议与失效触发器，变更后可段级覆盖且不引入失真，自检清单可执行。

及格线 Q2，目标 Q3。

## 6. 更新协议：只写现状，不写历史

**铁律：正文是当前状态的投影，不是变更记录。**

- 正文禁止变更叙事：不得出现“新增、修改、删除、旧版、已移除、不再、本次、曾经、改为、从 X 到 Y”等表述。
- 允许现状限定词：“当前、为空、未启用、默认”等，但不得暗示“曾经不是这样”。
- 变更历史外置：变更原因、废止理由、迁移过程写入版本控制提交信息或独立归档，不进入正文；需要回溯时走版本历史。
- 覆盖后自检：读者能否从正文推断出“曾经是什么”？若能，改写。

### 6.1 变更类型与影响段落

| 触发条件 | 影响文档 | 覆盖动作 |
|---|---|---|
| 顶层模块增删 | 定位与链路、主引擎职责 | 段级替换 |
| 插件增删 | 插件层契约、业务闭环索引 | 段级替换 |
| 工具可见性变化 | AUP 协议与注册、业务闭环索引 | 改单行并复核口径 |
| 运行时坐标增删 | 生产坐标与运维 | 加/删一行，重跑四问 |
| 红线变化 | 生产坐标、红线与运维规程 | 段级替换 |
| 配置项变化 | 配置与模型策略 | 段级替换 |
| 依赖增删升级 | 默认不覆盖，除非引入新运行时坐标 | — |

### 6.2 覆盖策略

- 段级替换：保留段落标题与准入依据，整段替换为现状描述。
- 禁止全文重写；必须重写时先归档旧版。
- 废止内容直接删除，正文不设“已废止”折叠区。
- 每个事实断言至少满足一条：有稳定标识（文件名、配置键、命令名、工具名）、有可执行校验命令、有明确归属段落。

## 7. 反模式

- **快照化**：把某一时刻的文件清单当文档本体。
- **下钻化**：对非业务语义单元做文件级、函数级展开。
- **禁令化**：用具体禁止项替代准入判据。
- **无成本细节**：写入后不影响任何决策的细节。
- **口径混用**：同一指标用不同统计边界表述。
- **判据私有化**：只给结论，不给可复用判据。
- **变更叙事化**：正文出现历史变化痕迹。

## 8. 自检清单

1. 全文是否只出现一个可执行的启动入口。
2. 每条红线能否转成一个“拒绝动作”。
3. 每个异常场景能否在生产坐标文档找到至少一个查询入口。
4. 工具、插件、日志数量口径是否全文一致。
5. 新增条目是否都跑过四问并标注象限。
6. 随机抽取事实断言，是否都可追溯到稳定标识或校验命令。
7. 本次更新是否为段级覆盖；全文重写是否已归档旧版。
8. 反模式八项是否均未出现。
