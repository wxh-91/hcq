# 06 权限与审计

> 本文件定义工具执行前的身份判定、高危工具范围、审计记录口径。协议门禁与可见性见 [05_AUP协议与工具注册.md]；配置身份项见 [09_配置与模型策略.md]；网关外部鉴权与 peer 透传边界见 [12_插件生态与信任边界.md]。

## 1. 身份类别

后端 `plugins/core_utils/trust.py` 按优先级判定高危工具，返回放行依据 `main_admin` / `role_admin` / `trusted_local` / `mobile_key`：

| 身份类别 | 判定依据 | 高危工具权限 |
|---|---|---|
| 主管理员 | `cl.py` 主管理员标识 `DEFAULT_ADMIN` | 放行（依据 main_admin） |
| admin 角色 | 请求上下文 `role=admin`；角色来自 8084 注入的 `X-User-Role`，回环豁免为 local-admin/admin | 放行（依据 role_admin） |
| member 角色 | 请求上下文 `role=member` | 高危工具拒绝 |
| 可信本地来源 | 回环地址，或 `.env` 的 `TRUSTED_LOCAL_HOSTS` 显式列出的地址 | 放行（依据 trusted_local） |
| 专属 Key 回退 | 未带角色且非可信本地来源，携带与 `MOBILE_API_KEY` 恒定时间比对一致的专属 Key；期望 Key 为空时失败关闭 | 放行（依据 mobile_key） |
| 其他发送者 | 不满足上述任一条件 | 高危工具拒绝 |

- 会话前缀只用于记忆分桶，不赋予高危权限；身份判定不依赖会话前缀。
- 身份判定只用于工具门禁，不改变模型选择与工具可见性。
- 角色闸门在后端 AUP 执行层完成；8083 网关层只做身份识别、member 轨迹脱敏与管理端点闸门，不做正文正则拦截。

## 2. 高危工具范围

高危工具以 8083 网关 `HIGH_RISK_TOOLS` 清单与后端安全模块当前集合为准：

- 命令执行：`execute_shell`、`aup_execute_shell`、`run_bash_script`、`run_shell`、`win_shell`、`win_ui_automation`
- 文件改写：`write_file`、`replace_line`、`delete_line`、`insert_line`
- 媒体清理：`clean_media`
- 管理员变更：`add_admin`、`del_admin`

其余工具不做身份拦截，但仍经过注册中心可见性与汇聚点执行。纳入高危范围的工具应同步本文件与审计口径。

## 3. 权限检查顺序

工具在汇聚点执行前先过只读配置守卫，再做权限检查：

1. 参数归一化与只读守卫：命中受保护配置的改写意图直接拒绝。
2. 注册中心查询：工具不存在或已下线，返回对应提示。
3. 权限检查：高危工具按第 1 节判定；未放行则记录拒绝审计并返回拒绝原因。
4. 放行后执行，结果与耗时写入审计。

## 4. 审计记录

审计日志按行追加，每条记录包含：

- 时间戳；
- 工具名；
- 脱敏后的参数；
- 调用者标识；
- 状态：成功 / 失败 / 拒绝；
- 耗时；
- 结果预览（截断）。

参数脱敏规则：密钥、口令、令牌、机密字段打码；超长参数截断后追加截断标记。审计日志是越权核查与工具失败排查的第一证据源，坐标见 [10_生产坐标红线与运维规程.md]。

## 5. 拒绝与失败的区分

- **拒绝（denied）**：身份不满足高危门禁，工具未执行。
- **失败（failed）**：身份放行，但执行过程抛错或返回契约错误。
- **成功（success）**：工具按契约返回成功状态。

排查时先按状态区分：拒绝查身份判定，失败查工具实现与入参。

## 6. 何时查本文档

- HCQ-Core Desktop 或客户端通道调 shell 或文件改写被拦。
- 远程身份本应被拒却放行，或反之。
- 审计日志缺记录、参数未脱敏、状态归类不符。
- 高危工具纳入后权限口径未同步。
