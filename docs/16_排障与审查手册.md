# 16 排障与审查手册

> 本文件是单机单用户部署的故障定位与变更审查索引：只保留“先查哪、怎么判、改哪里”，不展开实现细节。端口与运维规程见 [10_生产坐标红线与运维规程.md]；插件契约见 [07_插件层与扩展契约.md]；工具协议见 [05_AUP协议与工具注册.md]。

## 1 拓扑与健康判定

| 坐标 | 角色 | 监听 | 健康判据 |
|---|---|---|---|
| 8082 | HCQ-Agent Core（`dz.py`） | 127.0.0.1 | `curl -s http://127.0.0.1:8082/api/strategy` 有 JSON 返回 |
| 8083 | 业务网关（`gateway:app`） | 0.0.0.0 | `curl -s http://127.0.0.1:8083/healthz` 返回 `ok` |
| 3080 | HCQ-Core Web（DSH 前端） | 127.0.0.1 | 浏览器可打开 `?token=...` 入口 |
| 8085 | KULA 监控 | 127.0.0.1 | 面板可读 |
| 8086 | 健康聚合 | 127.0.0.1 | 聚合接口有返回 |
| 3306 | MySQL（Windows 侧） | 127.0.0.1 | `Test-NetConnection 127.0.0.1 -Port 3306` |

局域网访问面只有 8083：Windows `portproxy` 把 `0.0.0.0:8083` 转到当前 WSL IP；8082 与前端只在本机回环暴露。系统没有独立鉴权进程，网关即入口，身份恒为坐在电脑前的管理员。

## 2 启动与重启

- 一键：`${PROJECT_ROOT_WIN}\start_all.ps1`（幂等，已在监听则复用；`-Status` 只体检）。
- 后端：`${PROJECT_ROOT}/ops/start_backend.sh 0`。
- 网关：`${PROJECT_ROOT}/ops/start_gateway.sh`（`--host 0.0.0.0 --port 8083`）。
- 前端：`${PROJECT_ROOT_WIN}\start_dsh.ps1`（`dsh web --port 3080`，token 从 `dsh_web_3080.log` 提取）。
- 局域网转发：`${PROJECT_ROOT_WIN}\refresh-lan-forward.ps1`（WSL IP 变化后重跑；需管理员权限）。

## 3 故障速查

| 现象 | 先查 | 处置 |
|---|---|---|
| 3080 打不开或登录过期 | `${PROJECT_ROOT_WIN}\dsh_web_3080.log` 末尾 `?token=` | 用最新 token 重开；重启 `start_dsh.ps1` |
| 8083 返回 502 / 连接被拒 | `wsl-gateway/uvicorn.log`、`gateway.log`；`ss -tlnp \| grep 8083` | 网关进程缺失则重跑 `start_gateway.sh` |
| 模型报 401 / 密钥无效 | `.env` 的模型 Key、`docs/09_配置与模型策略.md` | 换有效 Key 后重启后端 |
| 下载工具执行完但没有产物 | 工具返回的 `[FILE: id=...]`；`${PROJECT_ROOT}/downloads/files` | 查 `file_registry` 是否有记录、磁盘是否写满 |
| 附件链接 404 | `GET /v1/files/<id>`、注册表 `rel_path` | 文件被移动或未落盘；重新生成附件 |
| 监控抽屉一直显示 “—” | `http://127.0.0.1:8083/api/system_stats` | 网关未起或端口被改；核对前端 `hcq-overlay.js` 的 API 常量 |
| 局域网设备连不上 8083 | `netsh interface portproxy show all` | WSL IP 变更后重跑 `refresh-lan-forward.ps1` |
| 前端样式丢失、监控入口消失 | `dist/index.html` 的 `hcq-theme.css` / `hcq-overlay.js` 引用；`dist/assets` 是否存在两文件 | 从 `${PROJECT_ROOT_WIN}\frontend\` 复制回 `dist\assets`，确认 `index.html` 有两条引用 |
| 插件导入失败 | `dz.log` 的 `plugin import failed` | 单包失败不阻断启动；修该包 `__init__.py` 的导入链路 |

## 4 日志与状态坐标

| 载体 | 位置 | 何时查 |
|---|---|---|
| 后端主日志 | `${PROJECT_ROOT}/dz.log` | 工具异常、插件导入、模型调用失败 |
| 审计日志 | `${PROJECT_ROOT}/audit.log` | 高危工具、配置写入、管理指令 |
| 网关日志 | `${PROJECT_ROOT_WIN}\wsl-gateway\gateway.log`、`uvicorn.log` | 转发失败、上游不可达 |
| 前端日志 | `${PROJECT_ROOT_WIN}\dsh_web_3080.log`、`dsh_web_3080.err.log` | 打不开、token 失效 |
| 启动日志 | `${PROJECT_ROOT_WIN}\start_all.log`、`boot.log` | 启动顺序与端口占用 |
| 通知落盘 | `${PROJECT_ROOT_WIN}\_notify\YYYY-MM-DD.jsonl` | 定时任务、提醒、巡检报警 |
| 工具注册表 | `${PROJECT_ROOT}/tool_center/tool_center.db` | 工具缺失、schema 不对 |
| 附件库 | `${PROJECT_ROOT}/downloads/files`（含 `data/auth.db`） | 下载产物、附件 404 |

## 5 变更后审查清单

1. 端口：8082/8083/3080 是否都在监听；8083 是否仍为 `0.0.0.0`。
2. 网关：`/healthz` 与 `/api/system_stats` 是否都返回。
3. 前端：`dist\index.html` 是否仍引用 `hcq-theme.css` 与 `hcq-overlay.js`；两文件是否在 `dist\assets`。
4. 工具：`tool_center.db` 的 `is_active` 与 schema 是否能被模型读到（全量工具对唯一用户可见）。
5. 附件：随便生成一个小文件，走 `[FILE:]` 链接确认 200。
6. 缓存：`__pycache__` 是否清理；`logs/` 是否没有暴涨。
7. 文档：本次改动是否同步到对应模块文档，且 `00` 号只读文件未被改写。

## 6 红线

- `docs/00_元规范与更新协议.md` 只读，任何自动化与脚本不得写入。
- `config_center/settings.py` 与 `config_center/wcu_policy.json` 是人工控制台，禁止程序改写。
- 单用户部署不引入鉴权层、不引入公网穿透；局域网直达 8083。
- 高危工具（shell、文件改写、桌面操控）只对唯一管理员开放，调用前由模型自行判断风险。
