# 17 插件开发指南

> 本文件是新增能力的落地手册：包怎么建、工具怎么声明、参数怎么给、怎么自查。加载机制与既有插件清单见 [07_插件层与扩展契约.md]；协议与注册口径见 [05_AUP协议与工具注册.md]；生产坐标见 [10_生产坐标红线与运维规程.md]。

## 1 目录与加载

- 插件根：`${PROJECT_ROOT}/plugins/`；每个能力域一个子包，必须含 `__init__.py`。
- 启动时扫描全部含 `__init__.py` 的子包，按目录名字典序导入；`core_utils` 等全局辅助包先就绪。
- 单包导入失败只写日志，不阻断主程序与其他插件。
- 主引擎不硬编码任何业务插件；能力一律经注册中心暴露。

## 2 最小骨架

```python
# plugins/demo_tool/__init__.py
# -*- coding: utf-8 -*-
"""demo_tool —— 一句话职责。"""
from aup_core import aup_tool

from .impl import run_demo          # 实现放子模块，包内只做契约适配


@aup_tool(
    name="demo_run",
    description="[原子] 做一件明确的小事：输入 X，返回 Y。何时用：……；何时不用：……",
    category="general",
    is_danger=False,
    params_schema={
        "required": ["target"],
        "properties": {
            "target": {"type": "string", "description": "目标，例如 URL 或文件路径"},
            "timeout": {"type": "integer", "description": "超时秒数，默认 15"},
        },
    },
    suggestion_hint="失败时提示用户检查目标是否可访问",
)
async def demo_run(target: str, timeout: int = 15) -> str:
    return await run_demo(target, timeout=timeout)
```

装饰器导入后自动采集元数据进入注册中心，无需在启动脚本登记。

## 3 声明字段

| 字段 | 作用 | 约定 |
|---|---|---|
| `name` | 工具名（模型可见） | 小写下划线，全局唯一；与函数名可不同 |
| `description` | 模型选工具的唯一依据 | 以 `[原子]` 或 `[宏]` 开头；写清“做什么、何时用、何时不用、返回什么” |
| `category` | 分类聚合 | `system` / `file` / `web` / `media` / `general` 等既有取值优先 |
| `is_danger` | 高危标记 | 命令执行、文件改写、支付、删库等必须 `True` |
| `need_confirm` | 需二次确认 | 不可逆操作置 `True` |
| `params_schema` | JSON Schema 子集 | `required` + `properties`；每个参数一句话说明单位与默认值 |
| `suggestion_hint` | 失败提示 | 给模型看的“失败后怎么办” |

## 4 原子与宏

- `[原子]`：一步一动作，参数明确、可组合；检索、读文件、单次请求属于此类。
- `[宏]`：内部已编排多步，直接返回最终结果；下载整站视频、搜索并读全文、定时任务、备份属于此类。
- 宏工具内部不得再让模型拆步；原子工具不得偷偷串联多步网络请求。

## 5 内部结构与隔离

- 实现代码放子模块（如 `impl.py`、`downloader.py`），`__init__.py` 只做导入与装饰。
- 中间函数、探针、临时脚本不加装饰器，保持模型不可见。
- 工作目录与临时产物收敛在插件目录或统一的 `downloads/`，不散落到项目根。
- 跨插件复用优先走 `core_utils` 或注册服务，不在主引擎里拼装。

## 6 注册与可见性

- 注册表：`tool_center/tool_center.db` 的 `tools` 表；`schema_json` 决定模型看到的参数。
- 单用户部署下不存在角色分级：全部 `is_active=1` 的工具对唯一管理员可见；`roles_json` 字段保留但代码不参与过滤。
- 高危工具不放宽判断，只在 `is_danger` / `need_confirm` 上标注。

## 7 自查清单

1. `python -m py_compile plugins/<包>/__init__.py` 通过。
2. 重启后端后，`tools` 表出现该工具，`is_active=1`。
3. 让模型跑一次真实调用，确认参数名与 schema 一致（大小写、下划线）。
4. 失败路径有可读提示，不抛裸异常栈。
5. 高危工具走一次 `audit.log`，确认有记录。
6. `__pycache__` 不留、临时文件不留在项目根。

## 8 常见错误

| 错误 | 原因 | 修法 |
|---|---|---|
| 模型永远不选该工具 | `description` 太抽象或缺触发场景 | 补“何时用/何时不用”，必要时加关键词 |
| 参数报 `missing required` | `required` 与函数签名不一致 | 对齐参数名与必填项 |
| 工具没出现在注册表 | 包缺 `__init__.py`，或装饰器未执行 | 检查导入路径与异常日志 |
| 导入即崩 | 模块级写了网络/文件副作用 | 副作用移入函数体内 |
| 下载产物找不到 | 落盘目录与附件注册表不一致 | 统一走 `file_delivery.register_file` |

## 9 何时查本文档

- 新增一项能力，不确定该落到哪个包。
- 不确定该声明 `[原子]` 还是 `[宏]`。
- 工具已注册但模型不选、或参数对不上。
- 插件导入失败、加载顺序引发依赖未就绪。
