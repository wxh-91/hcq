# 03 意图与对话编排

> 本文件描述对话主链路的判定顺序、模型分支、工具循环与清洗规则。模块文件职责见 [02_主引擎职责.md]。

## 1. 主入口与模型选定

对话主入口接收会话标识、用户输入、会话类型与可选模型名。本轮唯一决定性输入是调用方传入的模型；未传入时取默认模型。编排层不按意图重新分类、不静默替换模型。

模型配置解析失败时如实报错，不回退到其他模型；解析与配置结构见 [09_配置与模型策略.md]。

## 2. 前置短路与固定指令

进入主对话前，编排层依次处理固定规则：

- 高置信度鉴权类规则在规则层物理短路：直接构建工具调用，结果由代码层按契约直判，不经大模型总结。
- 固定的知识库查询指令按关键词检索知识库并直接返回。
- 固定的记忆写入指令写入长期记忆并直接返回。
- 图片识别结果按会话消费，新图片文本拼入本轮输入。

## 3. 意图漏斗

意图判定为三层漏斗，前两层不调用大模型：

1. **本地规则层**：静态正则与物理短路规则，零 API。
2. **词库层**：可学习词库命中，附带命中置信度；词库载体见 [04_记忆与知识体系.md]。
3. **大模型判定层**：前两层未命中或置信不足时，交模型分类；置信阈值为 `INTENT_CONFIDENCE_THRESHOLD`。

低置信度不执行工具，转为追问。词库可在使用中学习新词条；命中计数与来源记录在词库库内。

## 4. 模型分支

按模型配置的 `kind` 与 `supports_tools` 分流：

- **C 端网页通道**（`kind=c-end-web`）：走 C 端封装，工具调用关闭，不装配工具 schema。
- **支持工具的 API 模型**（`supports_tools=true`）：装配工具 schema 进入工具循环。
- **不支持工具的模型**：不携带工具调用。

主 API 请求失败并命中失败前缀时，可熔断到 C 端兜底通道；主 API 正常时不触碰兜底。

## 5. 工具循环

- 工具循环上限为 `TOOL_MAX_ROUNDS`，模型可基于上一轮工具结果继续决策。
- 每轮工具调用经唯一汇聚点执行：可见性过滤 → 权限检查 → 审计 → 执行，见 [05_AUP协议与工具注册.md] 与 [06_权限与审计.md]。
- 工具业务失败按 AUP 契约直判回传；失败、超时与异常状态经记忆中心回写本轮历史，下一轮据此如实说明任务未完成及原因，不得谎称已完成；非契约类错误可检索技能库排错指南注入。
- 重型绘图/代码类工具命中后，本轮产物在交付后物理隔离上下文，避免长代码污染后续闲聊。
- 经验库在工具循环前检索高匹配历史轨迹，命中则作为参考注入；采纳与下轮纠正反馈回写计数，见 [04_记忆与知识体系.md]。

## 6. 上下文装载与压缩

- 历史统一经记忆中心获取，编排层不直写会话历史。
- 达到压缩判定阈值时先做记忆巩固压缩，再取上下文；历史条数超过 `MAX_HISTORY` 时裁剪。
- 令牌计数用于压缩判定；压缩阈值与记忆上限的配置位置见 [09_配置与模型策略.md]。

## 7. 输出清洗与交付校验

输出在返回前统一经清洗层：

- 强泄漏模式与弱泄漏模式拦截工具参数、内部格式等内部细节。
- UX 违规模式命中时返回专用违规标记，再由修正话术兜底。
- 剥离裸媒体链接、长参数链接与裸 JSON。
- 交付前做证据校验：回复须有真实工具结果支撑；缺证据时按规则补正或降级，不允许模型自由总结出未发生的结果。

## 8. 超时与异常兜底

- 全局超时上限为 `ASK_AI_GLOBAL_TIMEOUT`；特定重型任务模式在其自身时长限制内豁免全局截断。
- 超时与内部异常返回固定兜底文案并记录错误日志，不抛出未处理堆栈到聊天通道。

## 9. 何时查本文档

- 消息进了后端但走错模型或走错通道。
- 应调工具未调、不应调却调、工具结果未被使用。
- 回复泄漏内部参数、链接或 JSON。
- 上下文过早压缩、长对话失忆或超长。
- 主 API 失败后兜底行为不符预期。
