# 07 插件层与扩展契约

> 本文件定义后端 Python 插件的加载机制、有效插件包与接入契约。各插件的业务闭环与对外工具见 [08_业务闭环索引.md]；协议门禁见 [05_AUP协议与工具注册.md]。DSH 宿主/前端插件的拉取、校验与登记逻辑见 [12_插件生态与信任边界.md]。

## 1. 动态加载

- 加载器在启动时扫描插件目录下含 `__init__.py` 的子包，按目录名字典序导入；全局辅助包先于业务包就绪。
- 单个插件导入失败只记录错误，不中断其余插件与主程序。
- 主引擎不硬编码导入任何业务插件；能力经注册中心与服务名获取。

## 2. 当前有效插件包

| 插件包 | 职责域 |
|---|---|
| `core_utils` | 全局辅助：下载、签到、经验库、词库、情节、得分、媒体、通知桥、安全扫描等 |
| `crawler` | 站点采集与视频拉流转码的物理隔离单元 |
| `data_utils` | 数据处理、网络请求、鉴权抓取、文本提取与安全巡检原子工具 |
| `feishu_delivery` | 飞书文件与图片多模态投递 |
| `info_retrieval` | 联网搜索与网页正文提取 |
| `proposal_center` | 系统修改提案通道（运行配置只读守卫配套） |
| `scheduler` | 持久化多模式定时任务 |
| `system_ops` | 系统状态、文件操作与脚本执行本体 |
| `tasks` | 重型任务调度：神授、大型规划、多任务队列 |
| `visual_arts` | 数学函数、几何图形与代码绘图工具箱 |
| `windows_control` | Windows 物理世界操控：浏览器、shell、原生控件 |

插件目录下不含 `__init__.py` 的空目录不构成插件，不被加载，也不计入插件口径。

## 3. 扩展契约

引入一项能力的标准路径：

1. 在插件目录下新建独立包，内含 `__init__.py`；
2. 工具函数携带协议装饰器，声明描述、参数 schema、分类、危险标记与可见性；
3. 实现细节放在子模块，封装层只做契约适配；
4. 主引擎与既有插件不引入硬编码引用。

插件导入时装饰器自动采集元数据并进入注册中心；无需在启动脚本登记插件清单。

## 4. 隔离原则

- 每个业务域位于独立插件包，子进程工作目录、工作区与临时产物收敛在插件目录内，不受外部当前工作目录影响。
- 插件只通过注册中心暴露对外工具；中间节点、探针与内部脚本不直接对模型可见。
- 插件依赖自身实现子模块；跨插件复用优先走核心辅助包或注册服务，不在主引擎拼装。

## 5. 可见性与危险标记

- 工具是否对模型可见由注册中心可见性标记决定，见 [05_AUP协议与工具注册.md]。
- 高危标记与权限门禁配套；纳入可执行命令或文件改写能力时，必须同步高危口径，见 [06_权限与审计.md]。

## 6. 何时查本文档

- 引入能力不知落到哪个插件包。
- 插件导入失败、加载顺序导致依赖未就绪。
- 主引擎出现对业务插件的硬编码引用。
- 中间节点或内部脚本被模型直接调用。
- 判断某目录是否属于有效插件。
